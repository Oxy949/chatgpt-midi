# Индикация и нагрузка Voice — 29 октября 2026

Версия `0.9.2.dev0` развёрнута на Midi через ADB. Архивы `v090` и `v091`
сохранены отдельно. Команды проектов и режимов описаны в [VOICE_CONTROL.md](VOICE_CONTROL.md).

## Логотип

| Состояние | RGB-логотип |
| --- | --- |
| Загружается браузер / Voice | Янтарный |
| Голосовой интерфейс открыт | Бирюзовый |
| Ожидается ручная проверка браузера | Фиолетовый |
| Закрытие, ошибка запуска, завершение процесса | Восстановление штатных триггеров |

Индикатор использует только шесть RGB-зон логотипа и их sync-узел. Кольцо
и часы не перехватываются. Он показывает режим ChatGPT, не различая отдельные
фазы «слушает» и «говорит». Наличие индикатора само по себе не доказывает,
что удалённый Voice-сервис отвечает.

Перед первым изменением сохраняются brightness и активный trigger всех
19 управляющих каналов в приватный `logo-original.json` в каталоге состояния.
Обычное закрытие восстанавливает их; следующий запуск контроллера восстанавливает
сохранённое состояние после аварийного завершения. На устройстве проверено
возвращение всех 19 триггеров после команды `close`.
Ошибка LED не прерывает разговор и отражается в `status` как `indicator_error`.
Для отключения задайте `MIDI_INDICATOR=off` перед запуском сессии.

## Снижение отрисовки

Chromium получает `prefers-reduced-motion: reduce`. После обнаружения голосового
интерфейса контроллер сворачивает окно через CDP. Openbox в отдельном Xvfb
нужен для настоящего перехода страницы в `visibilityState=hidden`: одно лишь
скрытие X11-окна без оконного менеджера этого не обеспечивало.
Страница не переводится в frozen, аудиоустройства не отключаются.
Перед запуском, завершением разговора и ручной проверкой окно показывается.

```sh
python3 -m midivoice ui-show  # Вернуть окно в VNC
python3 -m midivoice ui-hide  # Снова свернуть
```

`MIDI_BROWSER_QUIET_UI=0` отменяет автоматическое сворачивание.
Openbox включён в установщик и общий жизненный цикл графической сессии;
у старой Alpine он устанавливается отдельно:

```sh
chroot /data/opt/midi-browser/alpine /sbin/apk add --no-cache openbox
```

В начале исследования наиболее нагруженный процесс Chromium занимал около
150% CPU (100% — одно ядро), позднее наблюдались около 110%. Эти замеры были
в разные моменты работы сайта и не позволяют приписать всю разницу сворачиванию.
В парном замере одного установившегося разговора, по 4 секунды на состояние:

| Окно | Все процессы Chromium | Самый нагруженный процесс |
| --- | --- | --- |
| Показано | 43.7% CPU | 23.2% CPU |
| Свёрнуто | 40.5% CPU | 21.2% CPU |

Это небольшая экономия отрисовки, а не доказательство устранения всех задержек.
При свёрнутом окне подтверждены активные потоки Chromium input/output в PulseAudio.
Для субъективной оценки плавности требуется повторная проверка рядом с колонкой.
Пользователь уточнил: заикается и замедляется сама речь. Сворачивание этого
не устранило. Для текущих проверок задано `MIDI_BROWSER_QUIET_UI=0`.
В общие флаги добавлены `--disable-background-timer-throttling` и
`--disable-renderer-backgrounding`, чтобы скрытое окно не замедляло таймеры.
Модель, аккаунт, VPN и глобальные ALSA-настройки не менялись.

## Выходной тракт в 0.9.2

Воспроизведена остановка host `aplay`: счётчик чтения не менялся, обе очереди
были заполнены примерно на 60 КиБ, аппаратный PCM оставался в `PREPARED`
с `hw_ptr=0`. `strace` показал повторяющееся ожидание ALSA timer.
Существенного давления на память в этот момент не было. Порог запуска 20 мс
помог при одном запуске, но нагрузочный прогон повторил остановку.

Теперь native SoX в Alpine преобразует 48 кГц / stereo в 96 кГц / 4 канала
`L,R,L,R` перед host ALSA. Штатный `default` / softvol / dmix получает родной
формат и не запускает встроенный Speex resampler. Это проверяемый обход
остановки; точная ошибка внутри firmware ALSA отдельно не локализована.
Частота аппаратного микрофона и `/etc/asound.conf` остались прежними.

Старая дополнительная pipe вмещала 65536 байт, то есть 341 мс при 48k/2ch.
Две новые pipe ограничены 8192 байт каждая: около 43 мс до SoX и 11 мс после.
При заполнении запись ожидает освобождения места; PCM не выбрасывается.
Это ограничение скрытой очереди, а не замер полной задержки ответа.

Прогон 18 секунд синтетического PCM с двумя процессами CPU-нагрузки завершился
без ошибок ALSA и остановки чтения. При опросе раз в 50 мс максимальный
измеренный перерыв чтения составил 60.8 мс. Весь `pacat` с запуском и drain
занял 22.918 с. Два последующих прогона по 6 секунд после простоя также
завершились; журнал содержал только стартовый underrun около 0.02 мс.
Тест native SoX проверяет точную длительность, дублирование каналов и амплитуду.
Плавность реального ответа ChatGPT после изменения ещё не подтверждена на слух.

## Измерение WebRTC

`python3 -m midivoice audio-stats` читает штатную локальную страницу
`chrome://webrtc-internals`. Для Chromium 149 отдельно запрашивается обновление
getStats. Выгружаются числовые счётчики, разрешённые состояния, возраст выборки,
потери, компенсированные отсчёты и задержки jitter buffer / playout.
SDP, адреса, ICE credentials, идентификаторы соединений, URL и содержимое
разговора не включаются. Семантика счётчиков описана в
[спецификации W3C](https://www.w3.org/TR/webrtc-stats/#dom-rtcaudioplayoutstats).
Постоянный фоновый опрос не запускается.

Для синтетической подачи PCM через существующий микрофонный FIFO предусмотрены
root-сигналы SIGUSR1/SIGUSR2 процессу `pulse_mic stream`: временно остановить /
возобновить пересылку аппаратного звука. Захват продолжает дренироваться.
Без продления пауза сама истекает через 10 секунд. Аудио пользователя не записывается.

Настоящий Voice сейчас показывает модальное сообщение «Достигнут дневной лимит»,
сброс в 21:49 по времени страницы; часовой пояс не установлен.
Исправлено распознавание такого окна: запуск возвращает `voice_limit_reached`.
Автоматические попытки разговора остановлены. Локальные PCM-тесты лимит не расходуют.

## Контроль ошибок

Контроллер подписывается на `Inspector.targetCrashed`: падение вкладки теперь
завершает ожидающие CDP-запросы с понятной ошибкой и освобождает логотип,
вместо ожидания голосовой кнопки до общего таймаута. Добавлен регрессионный тест.
Проверка состояния также выводит тип исключения, если сообщение пустое.
Экспериментальное V8 CPU-профилирование сопровождалось падением вкладки на этой
сборке Chromium; оно исключено из поставляемых команд. Песочница остаётся включённой.

Проверки 0.9.2: **185 тестов на Midi без пропусков**, 48.1 секунды;
на Windows — 153 пройдены, 32 платформенных пропуска. Ruff пройден.
Отдельно проверены реальные цвета Chat/Work, восстановление LED,
открытие проекта и возврат на главную. Счётчики WebRTC выбирают свежие соединения,
чтобы новые разговоры в том же Chromium не показывали статистику старых вызовов.
