# Рефакторинг v0.8.1-dev → 0.9.0.dev0

## Исходное состояние и решения

Исходник: `chatgpt-midi-full-git-v081.zip`, SHA256
`3d6c7e2b6b48e3df01bb1dc42a24b3a5c224f1cdf588e2bc6a38ed58c2214cfc`.
Архив пользователя не изменён. В рабочем Git-каталоге до импорта был только README.

Основные проблемы структуры:

- `cli.py` объединял аргументы, контроллер, socket API, состояние, login и probes.
- `browser.py` объединял параметры запуска, хранение conversation URL,
  CDP-транспорт, управление процессом и DOM-логику.
- Login/visible/headless скрипты повторяли запуск PulseAudio, ожидание устройств,
  volume, аудиомосты, Xvfb/VNC и cleanup с различающимся поведением.
- Настройки путей вычислялись во время импорта и оставались устаревшими при
  смене окружения. Аудиовыход зависел от модуля микрофона ради общих констант.
- Часть тестов проверяла конкретные строки внутри монолитных файлов; одинаковое
  поведение в другом модуле ломало такие тесты.

Код разделён по этим границам. Добавлены `VoiceBrowser`, `Settings`, `StateStore`
и общий клиент управляющего протокола. Дополнительных runtime-зависимостей нет.
Длинная история экспериментальных инструкций заменена этой сводкой; полная
предыдущая история остаётся в исходном архиве. Дублирующий `VERSION` удалён:
единственный источник версии — `midivoice.__version__`.
Удалён неиспользуемый `SpeakerSink`: рабочий выход звука обслуживает
`pulse_speaker`, а диагностический `speaker-test` сохранён.

## Изменения поведения

- Quasar и CLI читают один протокол: пропускают progress и ждут итоговый `ok`.
  Прежний Quasar-клиент читал одну строку и мог принять progress за отказ.
- `status` и `diagnose` доступны во время открытия диалога; `close` отменяет его.
- Quasar продолжает принимать команды во время открытия, включая отменяющий `close`.
- Умерший браузер больше не считается активным только по сохранённому `mode`.
- Сбой подготовки/запуска CDP закрывает созданные pipe-дескрипторы. EOF,
  частичные записи и остановка ожидающих запросов обрабатываются транспортом.
- Микрофон ожидает данные через `select`; динамик пишет с возможностью прерывания.
  SIGTERM не должен зависать на пустом/заполненном аудиопотоке.
- Фоновые сервисы наблюдаются в течение всей сессии, а их сбой завершает сессию.
- JSON состояния заменяется атомарно приватным временным файлом. Пути профиля
  проверяются после нормализации, включая `..`; адреса внутри chroot используют `/`.
- Добавлен `MIDI_STATE_DIR`; логи сессий следуют за выбранным `MIDI_ALPINE_ROOT`.
- Проверки браузера используют отдельный временный профиль; при таймауте
  завершается вся группа дочерних процессов. PSS учитывает потомков,
  созданных рабочими потоками Chromium.
- Ошибки CLI возвращают ненулевой код и понятное сообщение. SIGTERM сервера
  выполняет cleanup и считается штатной остановкой.

## Совместимость и перенос

Сохранены команды CLI, форматы conversation/diagnostic JSON, имена PulseAudio
source/sink, расположение профиля Alpine и четыре прежних скрипта запуска.
Внутренние Python-импорты изменились: `Controller` находится в `controller.py`,
launch helpers — в `browser_launch.py`, сохранение URL — в `StateStore`, общая
подготовка аудио — в `pulse.py`. Внешние Python-скрипты с прежними импортами нужно
обновить; слой устаревших Python-алиасов не добавлялся.

Для обновления уже настроенной станции:

1. Остановить текущую сессию; при необходимости использовать `stop-all.sh --dry-run`.
2. Заменить исходники, скопировав также новые `scripts/lib/`, `run-voice.sh` и
   `login-browser.sh`. Профиль и Alpine находятся вне исходников.
3. Проверить `python3 --version` (нужен 3.11+), восстановить executable bit
   `scripts/midi-chromium` и запускать из корня проекта, как прежде.
4. Запустить `run-visible-voice.sh`, во втором терминале выполнить `open`, затем
   проверить `status`, `snapshot`, звук, `close` и полную остановку сессии.

Первичную установку Alpine повторять для этого рефакторинга не требуется.
Если используется `MIDI_STATE_DIR`, сервер, CLI и Quasar должны видеть одно значение.
Login с включённым аудио теперь явно требует установленные аудиозависимости;
для настройки только аккаунта/VPN используйте `MIDI_LOGIN_NO_AUDIO=1`.

## Проверка и оставшиеся ограничения

Локально проверены Python 3.14.3 / Windows, Ruff и синтаксис POSIX shell через
Git Bash. Тесты покрывают контроллер, протокол, ошибки/очистку CDP, state,
аудиоформаты и shell-сценарии с подставными сервисами. Проверки POSIX-only
помечены отдельно; CI добавлен для Linux/Windows и Python 3.11/3.13/3.14.

На Миди через ADB выполнен полный прогон 145 тестов без пропусков, включая
настоящий Chromium в отдельных профилях, CDP-pipe и нативный SoX. Запущены Xvfb,
PulseAudio, микрофон 96 кГц → SoX → 16 кГц и воспроизведение через ALSA default.
Проверены закрытие браузера и полная остановка проектных процессов.

Воспроизведённый SIGTRAP устранён восстановлением proc и `/dev/shm` внутри
Alpine. На авторизованной странице обнаружена ручная проверка Cloudflare;
пользователь прошёл её в обычном Chromium через VNC, после чего CDP-запуск
тоже открыл ChatGPT. После включения временного zram и перезапуска проекта
пользователь подтвердил слышимый ответ и закрытие/открытие командами Алисы.
По живой диагностике исправлен подсчёт PSS на ядре без файлов `children`;
три профильных теста пройдены на Windows и Midi. Продолжительный разговор
и качество AEC не проверены. Запуска CI не было.
Ускорение браузера и снижение RAM сравнительным тестом не измерялись.
Подробности заимствованных подходов — в [UPSTREAM_REVIEW.md](UPSTREAM_REVIEW.md).
