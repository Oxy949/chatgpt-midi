# Голосовое управление с колонки — 29 октября 2026

В `0.9.2.dev0` Quasar-адаптер входит в общую сессию `run-voice.sh`.
Он переподключается к локальному IPC прошивки и завершается вместе с сессией.
Достаточно запустить `scripts/run-visible-voice.sh`; отдельный listener не нужен.
Автозагрузка станции и прошивка этим изменением не перенастраивались.

## Команды

| Фраза после «Алиса» | Результат |
| --- | --- |
| «Открой чат джипити» | Открыть голосовой разговор |
| «Закрой чат джипити» | Завершить разговор и освободить браузер |
| «Чат джипити, новый чат» | Новый разговор в текущем проекте или вне проекта |
| «Открой новую вкладку в чат джипити» | То же, без дополнительного процесса Chromium |
| «Открой проект Название в чат джипити» | Найти существующий проект по полному имени |
| «Чат джипити, работа» | Выбрать «Работа» |
| «Чат джипити, чат» | Выбрать «Чат» |
| «Переключи чат джипити в режим работы» | Выбрать «Работа» |
| «Чат джипити, главная» | Выйти из проекта |

Название проекта сравнивается целиком, без учёта регистра и пунктуации.
Распространённые произношения ChatGPT в названии также приводятся к одному виду.
Если имена совпадают у разных проектов, открытие отклоняется. Новые проекты
не создаются. Произвольные URL, JavaScript или shell-команды из речи не принимаются.
Обычные команды Алисы без названия ChatGPT адаптер не перехватывает.

Проект и режим сохраняются в приватном `navigation.json`. Новый разговор
сохраняет выбранный проект. Навигация заканчивает текущий Voice перед переходом
и возобновляет его, если он работал; из ожидания открывается только интерфейс.
`close` отменяет и загрузку Voice, и переход к проекту/режиму.

Переключение использует настоящие кнопки страницы и проверяет `aria-pressed`.
Проекты выбираются по видимым строкам боковой панели; успешное открытие
подтверждается URL страницы проекта. Приватные API сайта не используются.
Назначение режимов описано в [официальной документации OpenAI](https://learn.chatgpt.com/docs/web).

## Почему одновременно включалась музыка

Раньше отмена штатного ответа Алисы отправлялась после полного запуска Voice.
За это время прошивка успевала выполнить свой сценарий, в том числе включить трек.
Теперь локальный контроллер отправляет `accepted` до долгой загрузки, и адаптер
сразу отменяет именно распознанный запрос по его request ID.

После перехода Алисы в IDLE допускается один запрос паузы проигрывателя.
Он ограничен пятью секундами после принятой команды. Следующее пробуждение
Алисы отменяет отложенную паузу; периодического подавления музыки нет.
Речь, request ID и названия проектов в журнал адаптера не записываются.

Протокол отмены и паузы адаптирован по описанию взаимодействия с Quasar в
[исследуемом проекте](https://github.com/rison1337/Alisa-ChatGPT-voice-assistant/blob/1ec30394332728c25d65322459515001d5bd53c7/engines/bridge/station/native_agent.c).
Нативные бинарники или аудиохуки того проекта не устанавливались.

## Индикация

| Состояние | Логотип |
| --- | --- |
| Загрузка / переход | Янтарный |
| Интерфейс «Чат» | Синий |
| Интерфейс «Работа» | Лиловый |
| Voice открыт | Бирюзовый |
| Ручная проверка браузера | Тёмно-фиолетовый |
| Закрыто | Штатные триггеры прошивки |

Индикация сообщает состояние контроллера, а не гарантирует сетевое подключение
или слышимый ответ. Кольцо и часы остаются штатными.

На Midi проверены реальные переключатели «Чат / Работа» и открытие проекта.
Проверены возврат на главную, совпадение всех 18 цветовых каналов логотипа
и восстановление штатных триггеров при закрытии. Пакет паузы доставлен
в локальный Quasar; это не подтверждает результат на слух.
Тестами покрыты ранняя отмена до завершения медленного запуска, дедупликация,
отложенная пауза, отмена при следующем пробуждении и гонка открытия с закрытием.
Слышимость ответа и отсутствие трека при настоящей голосовой команде после
этих изменений требуют повторной проверки. Дневной лимит Voice на аккаунте
сейчас не позволяет проверить разговор целиком.

Полный набор: 185 тестов на Midi без пропусков (48.1 с), 153 пройдены на Windows
с 32 платформенными пропусками. Линтер Ruff пройден. После уточнения выбора
свежих WebRTC-соединений повторно пройдены 12 DOM-fixtures Chromium (31.9 с).
